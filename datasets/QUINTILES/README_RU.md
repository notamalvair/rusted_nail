# Каталог квинтилей PumpAPI

Этот каталог — компактный справочник распределений поверх полных Parquet из соседних папок трёх дат. Он **не заменяет исходные события**, не содержит PnL/исходов стратегии и не делает исходные данные полностью валидированными.

## Файлы

- `metric_catalog.duckdb` — самодостаточная DuckDB с таблицами `catalog_run`, `metric_definition`, `metric_distribution`.
- `quintile_thresholds.parquet` — переносимая таблица порогов и диагностик.
- `metric_definitions.parquet` — описание метрик, единиц и применимости.
- `catalog_run.parquet` — provenance и версия политики.
- `assign_quintile.sql` — пример присвоения Q1–Q5.
- `BUILD_REPORT.json` — итоговая проверка маленьких выходных таблиц.
- `RUN_STATUS.json` — состояние построения.

## Что означает квинтиль

Для подходящей группы сохраняются приблизительные границы `p20`, `p40`, `p60`, `p80`:

```text
value <= p20 → Q1
value <= p40 → Q2
value <= p60 → Q3
value <= p80 → Q4
value >  p80 → Q5
```

Метод: DuckDB `approx_quantile` после `TRY_CAST(decimal_text AS DOUBLE)`. Исходные точные строки Decimal остаются в полных Parquet; пороги приблизительные и не восстанавливают утраченную провайдером on-chain точность.

`NTILE(5)` не использован: одинаковые значения не разбрасываются искусственно по корзинам. Если границы нестрогие или `n_valid < 1000`, `quintiles_eligible=false`, а причина находится в `ineligible_reason`.

## Группы и fallback

1. `DAY_ACTION_PROTOCOL` — конкретный двухчасовой день + action + protocol.
2. `ACTION_PROTOCOL` — те же action/protocol по трём датам.
3. `ACTION` — action по трём датам, если более узкие пороги непригодны.

При fallback нельзя менять action, слой или валюту. Для quote-метрик обязательно совпадение `quote_mint`.

## Два независимых слоя

- `parent_event` — верхнеуровневые агрегаты и снимки состояния пула.
- `event_leg` — операции breakdown.

Их нельзя складывать: parent может быть netting, а legs — детализация той же транзакции/события.

## Единицы

- quote amount/price/market cap/reserves разделены по `quote_mint`;
- SOL/USD метрики имеют свои единицы;
- base-token amounts/supply/reserves описаны как human base units и не являются одинаковой экономической величиной между разными mint;
- fee rate — доля, не процентные пункты;
- reported network fee может повторяться в нескольких событиях одной signature.

## Диагностика

Каждая строка содержит `n_rows`, null/cast-fail/nonfinite, negative, zero, valid count, min, p01, p20, p40, p60, p80, p99 и max. Отрицательные значения исключены из расчёта порогов, но посчитаны отдельно.

В 613 крошечных all-zero группах DuckDB `approx_quantile` первоначально вернул минимальное положительное DOUBLE (`2.225e-308`) выше фактического max=0. Эти группы всё равно были непригодны из-за малого `n_valid`; перед финальным экспортом все приблизительные квантили ограничены наблюдаемым диапазоном `[min_value,max_value]`. После исправления нарушений монотонности нет.

Статус источника наследуется как `written_unvalidated`: полные Parquet записаны и имеют совпадающие footer counts/schema, но их полная сверка с исходными `.zst` отменена по просьбе пользователя. Каталог не исправляет и не скрывает этот статус.

## Ограничения

- Три независимых двухчасовых окна с недельными разрывами — не непрерывная история.
- Это распределения исходных метрик, а не карточки токенов, ранние окна 5/15/30/60 секунд или доходности.
- Квинтиль не является торговым сигналом и не доказывает прибыльность.
- Для Rust достаточно загрузить маленький `quintile_thresholds.parquet` или DuckDB и применить fallback; полные Parquet пользователь передаёт отдельно для replay/feature engineering.
